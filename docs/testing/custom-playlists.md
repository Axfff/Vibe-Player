## 测试数据与隔离约定

使用专门的测试设备或测试配置，以及三份可恢复的本地测试音频：**A、B、C**。三首曲目应可正常播放、能在曲库中明确区分，并使用不同的实际音频文件；A/B/C 是本计划的别名，不要求 APP 显示这些字母。让实际文件名和歌曲标题都按 A、B、C 的对应关系升序排列，例如 `test-a.mp3` / `Test A`，以保证 [C, A, B] 不等于名称排序。播放用例优先使用短音频，便于观察自然切歌。

每个用例都重新建立自己规定的输入状态，**不继承上一个用例的最终状态**。开始前停止播放，恢复 A/B/C 文件并刷新曲库，确认其均可播放，再清理本计划使用的测试歌单。歌单编辑测试期间保持播放器停止。对特定用例有意义的播放操作在步骤中明确写出。

| Fixture | 每次重新建立的起始状态 |
| --- | --- |
| **F0** | A/B/C 均存在于曲库且可播放；没有自定义歌单；播放器停止。 |
| **F1** | 从 F0 建立 Study = [A, B]、Running = [B, C]；方括号表示逐首添加得到的保存顺序；播放器停止。 |

如用例准备依赖尚未实现的创建/添加能力，则标记 `Blocked` 并记录原因，不通过修改应用内部存储来伪造可用界面。重置测试环境只能发生在用例开始前或结束后，不能发生在一次持久化验证的“修改—重启—检查”之间。

### 本文中的“重启 APP”（R）

完成操作并确认界面显示成功后的状态，在系统应用设置中将被测 APP 强行停止，再重新打开**同一台设备上的同一安装**。这一方式用于确保应用进程和可能存在的播放服务均已停止；仅切换到后台或划掉最近任务不能直接当作已完成本计划的 R。

R **不包括清除应用数据、卸载或重新安装、替换安装包、切换测试账号/配置**。这些操作可能改变测试数据，不能用于证明 AC7。记录实际采用的停止和重开方式，不假定新打开的界面一定来自持久化恢复。
